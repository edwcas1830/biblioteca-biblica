# Biblioteca Bíblica 0.3 — revisión local

Esta versión conserva el diseño anterior. Implementa almacenamiento personal en SQLite y lectura de paquetes locales con Biblias, diccionarios y comentarios. El diseño A y las conexiones de IA pertenecen a la siguiente iteración.

## Almacenamiento y recuperación

`lib/personal-store.cjs` guarda `biblioteca-personal.sqlite` dentro de `userData`. Notas y subrayados tienen referencias de libro estables (`b001`…`b066`); posición y lecturas de planes almacenan `bookId`. Cada plan conserva su ID y cada día tiene un ID independiente de su posición. El progreso pertenece al día; la interfaz conserva el formato anterior para importar/exportar copias.

La primera migración respalda el JSON original en `respaldos/legacy-v1-<huella>.json`, escribe en una transacción y conserva intacto el localStorage anterior. Un fallo revierte las escrituras y permite reintentar. Después, SQLite prevalece sobre esa copia antigua. Volver a 0.2.1 recupera el estado anterior a la migración; **no incorpora cambios realizados después en 0.3**. Para recuperación completa se utiliza «Exportar copia» y «Recuperar copia».

Las notas anteriores siguen asociadas a RV1909. Las nuevas notas se separan por versión: `rv1960@b043:3:16`, por ejemplo. No se supone equivalencia de numeración entre fuentes ni se mueve automáticamente una nota a otra edición. La fuente RV1909 incluida contiene 18 posiciones vacías y usa numeración diferente en algunos capítulos.

`lib/library-worker.cjs` procesa datos y búsquedas fuera de la interfaz. Preload solo expone operaciones concretas; Electron mantiene aislamiento, sandbox y ausencia de Node en la página.

## Paquetes admitidos

Se buscan `userData/modulos/<paquete>/manifest.json` y `resources/modulos/<paquete>/manifest.json`. La app no necesita una instalación de e-Sword. Esta versión no incorpora todavía el asistente de copia/importación.

El manifiesto contiene `modulos`, una lista de objetos con `id`, `tipo`, `rol`, `archivo`, `titulo`, `bytes` y `sha256`. `registros`, `origen`, `licencia` y `versificacion` completan la identificación. Si no hay licencia individual, se muestra el aviso `uso` del paquete y el aviso bibliográfico incluido en `Details.Comments`; esto **no constituye un permiso de redistribución**.

Compatibilidad declarada:

- `.bblx`: SQLite sin cifrar, tabla `Bible(Book,Chapter,Verse,Scripture)`, libros 1–66, referencias dentro de las cotas del canon protestante. Se conserva la numeración de cada módulo.
- `.cmtx`: `Books` y `Chapters` opcionales; `Verses` con `Book`, `ChapterBegin`, `ChapterEnd`, `VerseBegin`, `VerseEnd`, `Comments`. Los rangos incluyen ambos extremos, también al cruzar capítulos.
- `.dctx`: `Dictionary(Topic,Definition)`. Strong, Vine AT/NT agrupado y Vila-Escuain aparecen como tres diccionarios.
- Los paquetes son copias cerradas: se rechazan rutas externas, enlaces, huellas incorrectas, registros WAL/journal/shm externos, módulos cifrados y esquemas incompatibles. `.topx`, `.mapx` y formatos adicionales quedan pendientes.

RTF se convierte en tokens y HTML escapado: texto, negrita, cursiva, encabezados, saltos, Unicode y los juegos de caracteres griego/hebreo de los fragmentos e-Sword. Se ignoran objetos, imágenes, instrucciones de campos y destinos ejecutables. No pretende reproducir toda la maquetación RTF. El rojo procede de `cf6`, solo en el NT; superíndices de anotaciones como `(A)` no se colorean ni se leen como texto bíblico.

Los números Strong se esconden al abrir la app. En RV1960 se combinan con `rv1960-strong` solo cuando coincide el texto normalizado. Si difiere, se conserva el texto principal, se muestran los números al final y se avisa. El vínculo palabra→original queda para v0.4.

## Búsqueda, revisión y voz

FTS5 indexa cada Biblia por módulo y SHA-256; elimina diferencias de tildes. Ofrece búsqueda por prefijos, palabra completa y número Strong. La primera búsqueda prepara el índice local; sus resultados están limitados a las primeras 100 coincidencias, mostrando el total.

Un cambio detectado invalida la fuente anterior. «Comprobar paquetes y revisiones» relee manifiestos y huellas; con un manifiesto actualizado, la siguiente búsqueda reconstruye el índice. Las referencias de resultados conservan módulo y revisión; una referencia antigua no se abre como si perteneciera a la nueva fuente. El índice puede reconstruirse y no contiene el estado personal.

La lectura en voz alta usa exclusivamente voces locales en español disponibles en Windows. Hay pausa, continuación y detención. No requiere internet ni envía texto a una voz externa. Si falta una voz, la pantalla lo indica.

## Distribución y pruebas

Los módulos personales no están en Git ni en el instalador. Las exclusiones del empaquetado refuerzan `.gitignore`. El instalador de evaluación incluye RV1909; el 3+3+3 aparece con el paquete personal instalado en el perfil correspondiente. Las fuentes libres adicionales del consenso se incorporarán cuando estén preparadas y verificadas.

`BIBLIOTECA_TEST_PROFILE` selecciona un perfil separado y desactiva las consultas de actualización. `BIBLIOTECA_TEST_HIDDEN=1` requiere ese perfil y habilita capturas solo durante las pruebas. Nunca debe usarse un perfil real para el script `scripts/smoke-windows.cjs`.

Ejecutar las pruebas con `npm test`; generar Windows con `npm run build:win` (publicación desactivada). La entrega y las evidencias de pruebas de esta PC están en `../mesa/V03-ENTREGA.md`.
